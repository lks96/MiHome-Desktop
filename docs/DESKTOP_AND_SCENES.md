# 场景与桌面功能

## HA 场景

智能场景页从已同步的 `scene.*` 实体生成列表，支持名称/ID 搜索、收藏和一键执行。收藏保存在 SQLite `scene_favorites`，不改变 HA 场景。

执行流程复用经过校验的 REST 服务入口，仅允许调用该实体的 `scene.turn_on`，不自动重试或向任意目标组注入参数。尚未激活过的场景可能显示 `unknown`，这不等于不可用；`unavailable`、实时连接中断或服务注册表未声明操作时禁用执行。

执行期间禁用同一场景按钮。HA 返回成功只表示服务请求已处理，界面不伪造物理设备变化或激活时间；后续状态仍由 HA 实时事件更新。

## 托盘与窗口

Windows 桌面端初始化系统托盘，提供“显示主窗口”和“退出”。左键点击托盘恢复并聚焦主窗口。

“关闭窗口后留在托盘”默认关闭，需用户在设置中启用并保存。开启且托盘可用时，关闭主窗口改为隐藏；托盘不可用或隐藏失败则允许正常退出，避免窗口消失后无法恢复。

窗口隐藏或页面不可见时，监控播放器关闭 PeerConnection、停止轨道并释放会话；恢复后重新建立当前可见画面的播放。HA 连接可以继续在后台维护。

窗口大小、位置和最大化状态由官方 window-state 插件保存。不会持久化隐藏、全屏状态，以免下一次启动不可见。

## Windows 开机启动

使用官方 autostart 插件，默认关闭。设置保存时，仅在开关改变后修改系统注册。若数据库保存失败，则尝试还原原来的系统注册；还原失败会返回明确错误，用户应检查 Windows 启动应用设置。

界面同时显示应用偏好和系统当前启动注册状态。外部手动更改 Windows 启动项可能让两者不同；应用不会在每次启动时强行覆盖系统设置。

NSIS 安装方式为当前用户，卸载钩子清除本应用的当前用户 Run/StartupApproved 注册值。用户配置与凭据不由该钩子删除。Windows 安装、启动、托盘恢复、卸载清理仍需原生验收。

## 日志与诊断

新日志为按日轮换的 JSON，保留最近 7 个日志文件。诊断页显示版本、平台、HA 连接状态、重试次数、错误码及实体/场景/摄像头数量。

导出前需要勾选隐私说明，然后在原生保存对话框中选位置。取消对话框不会写文件。诊断包为 JSON，包含状态摘要和严格白名单筛选的日志：

- 只导出审核过的静态消息、有效时间戳和级别。
- 不复制数据库、系统凭据、认证头、Token、任意日志字段、SDP、视频 URL、设备名称或局域网地址。
- 旧版纯文本、无法解析或未知消息会省略并计数。
- 最多读取最近 7 个匹配日志文件，单文件最多 1 MiB，总计最多 4 MiB；忽略符号链接。
- 使用临时文件写入并落盘，成功后替换用户选择的导出文件。

白名单策略有意省略部分诊断细节，后续新增可导出字段需要单独审查，不应直接把原始日志全文加入诊断包。

## 验证边界

Rust 测试覆盖场景参数、实际本地 HTTP 请求、未提前修改缓存状态、收藏持久化、旧偏好兼容及诊断信息过滤。浏览器测试覆盖场景执行反馈、待执行状态防重复、托盘隐藏事件释放/恢复视频，以及启动偏好提交和导出确认/取消。

浏览器测试不会修改 Windows 注册表或测试原生文件对话框；这些原生功能需随最终 Windows exe 在实机验收。


发布配置包含显式 CSP，仅允许打包脚本、应用样式、图片数据和媒体对象；HTTP 业务请求由 Rust 执行，前端没有任意外部 fetch 权限。开发 CSP 额外允许本地 Vite HMR。官方插件通过 Rust 使用，未安装不需要的前端插件 SDK，也未给前端授予文件系统、Shell 或启动项管理权限。最终 CSP/WebView2 行为仍需随 Windows 包验证。
