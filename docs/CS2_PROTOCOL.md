# CS2 远程实现与验证边界

本项目以用户提供的技术方案为线索独立实现 Rust 协议，不复制无许可证的 micam Java 源码、测试或二进制。协议研究依据固定为 [micam 2cc9d9e](https://github.com/eugeneRover/micam/tree/2cc9d9e7607014d1d05c17bc5676544fbb0d5d24)、[MIT PPPP 文档](https://github.com/magicus/pppp-dissector/tree/3ea9a7261f028fe2c75d141cb430bc29a162e2b0) 与既有 go2rtc MISS 资料。测试使用本项目生成的协议材料和视频，不含真实账号、摄像头标识或流量。

## 已编写的链路

1. 复用当前扫码会话，校验设备属于账号、在线、型号为 `chuangmi.camera.039a01`。为播放生成新 X25519 密钥对，用同一公钥申请 `/v2/device/miss_get_vendor`；严格解析 `vendor.vendor_params.p2p_id` / `init_string` 与结果层的 `public_key` / `sign`，不复用旧探测报告。
2. 解码 A–P nibble / 54 字节协议表 / running XOR 的 init string，校验 IPv4、数量和长度。拒绝私网、回环、多播、非法地址；不编译固定服务器列表。服务器参数不出后端。
3. 向授权参数中的会合节点 UDP 32100 发 `0x67`，收集合法来源的 `0x82` 候选及每份 token，分别注册 `0x83`、Hello `0x70` / `0x71`、端口分配 `0x72` / `0x73`。向会合节点提交 `0x80`，向协商会话端口发注册包打开 NAT 映射，等候选会话端口返回 `0x84`。每阶段有限重试，总握手有时限。仅实现 Relay，未实现直连打洞或 TCP fallback。
4. UDP socket 固定连接到所选会话端点；完成 `0x28` 的 88 字节会话连接回复，处理重复请求；0.3.1 起忽略确认/非请求消息，避免误送请求改写器而中断认证。DRW 外层大端长度、通道与序号；通道 0 控制、通道 2 媒体。支持 1024 字节发送分片、乱序重组、重复 ACK、16 位回绕、发送重发、ACK 超时、缓冲和队列上限、保活与关闭。
5. MISS `0x100` 明文认证，在固定命令头识别大小端 `0x101`（以及一层 `0x1001` 认证信封），清除尾部 NUL/空白与 UTF-8 BOM 后严格解析单个 JSON result，不按子串认定成功；拒绝重复 result 和非填充尾随数据。X25519 后执行 HSalsa20（NaCl box precompute），拒绝退化共享密钥；命令按 ChaCha20 随机 8 字节 nonce 封装为 `0x1001`。启动 `0x102`，画质支持 0/1/2（自动/流畅/高清），默认保留质量 2、声音关闭。
6. 媒体头为 32 字节、字段小端，与 CS2 外层分开处理。校验长度、codec 4/5、nonce、Annex-B 前缀；从关键帧启动。H.264 重封装，H.265 在 Windows 以 FFmpeg 软件解码并调用 `h264_mf` 编成 H.264，输出 HLS。0.3.2 移除固定 `-r 20`：将摄像头 access unit 及规范化的 PTS/PCR 装入 MPEG-TS 输入，输出使用 `fps_mode=passthrough`。缺失/倒退时间戳优先参考近期有效间隔或网络接收节奏。H.265 编码使用低延迟标志、无 B 帧和更短 GOP；hls.js 使用两段直播同步目标，保持 1 倍播放速度。
7. HLS 仅在随机 `127.0.0.1` 端口提供，独立随机路径 token；校验 Host、Origin、文件名与大小，不允许目录遍历。页面通过 IPC 只取得安全状态与本机媒体地址。hls.js 在 WebView2 中解码；只有视频帧回调才显示“正在播放”。
8. 按原生窗口 label 绑定和隔离会话，单设备默认一条会话、最多两路。停止、嵌入抽屉关闭、主窗口隐藏会清理对应主窗口会话；独立观看窗可继续播放，关闭观看窗清理其会话。退出账号或程序清理全部会话和观看窗口；后端 lease 防止页面丢失后常驻取流。发送 VIDEO_STOP / CLOSE，杀死并等待 FFmpeg，关闭 HTTP/UDP 与缓存；异常强制中止另由 kill-on-drop 兜底。前端故障最多自动重试三次，每次重新取得授权。

## 使用与诊断

安装完整包后扫码 → 摄像头卡片“播放”，直接打开独立观看窗口并开始连接。全屏由原生窗口处理，可按 Esc 退出；“小窗模式”调整同一观看窗口尺寸并置顶，不重建视频会话。画质切换会重建该设备的视频连接，默认高清；具体分辨率以实际视频为准。不要只拷贝主 EXE，便携版须保留同目录 `ffmpeg/`；Windows N/精简系统可能缺少 Media Foundation，需要安装微软 Media Feature Pack。其他型号仍显示待适配。

Schema 4“连接结果”可复制客户端版本、阶段、失败阶段、错误码、耗时、媒体包/关键帧数、codec、前端已解码帧数，以及认证结构和传输计数，不包含 did、签名、私钥、UID、中继地址/token 或媒体 URL。新增时间戳采样/回退次数、估计源帧率、实际网络重组后的接收帧率、最大到达间隔与写入编码器耗时，以及播放分辨率、显示帧率、掉帧/等待次数、前向缓冲和 HLS 直播边缘距离（这不是端到端摄像头延迟）。`remotePlaybackVerified` 为本次尝试是否观察到解码帧；旧“检测视频授权”报告仍固定为 false。

## 验证范围

已加入模拟 UDP 会合/Relay/`0x28`/丢包重发测试、乱序/回绕/长度边界测试、NaCl 公开固定向量、授权材料绑定与账号归属测试，以及生成 H.264/H.265 → 实际 HLS → 独立解码测试。浏览器测试覆盖阶段显示、失败、迟到响应与关闭清理。

用户已提供 v0.3.1 的实机出画报告：H.265、约 61 秒、573 个媒体包、521 次解码帧回调，认证无错误。随后回报“停住后跳动/快进”，因此新增时间轴优化。生成视频测试使用标称 20fps 编码元数据和实际 10fps 的逐帧 PTS，独立 ffprobe 核对全部 40 帧的 100ms 间隔，避免仅按播放列表末段估计时长判断。

v0.3.2 的流畅度、置顶/全屏/多窗口原生行为与 30 分钟稳定性仍待用户 Windows 实测，不泛化到其他 CS2 型号。无音频、对讲、云台或录像回放。
